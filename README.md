# christmas-village

크리스마스가 도착하는 마을: a short interactive Christmas experience. Open five gift boxes, deliver each one to a house in a sleeping pixel-art village, and watch the windows light up until the central tree glows. The finished village can be saved and shared as a 9:16 Christmas card.

Everything runs in the browser. There is no backend, database or login. Progress is kept in LocalStorage.

## Commands

Requires Node ≥ 22.18. The asset script and the tests run TypeScript natively, without a build step. `.nvmrc` pins Node 26.

```bash
pnpm install
pnpm dev               # http://localhost:3000
pnpm build && pnpm start
pnpm lint              # ESLint
pnpm typecheck         # tsc --noEmit (strict)
pnpm test              # node:test, game rules + storage validation
pnpm format            # Prettier (format:check in CI)
pnpm assets:generate   # regenerate every sprite, the OG image and the favicon
```

During development, `/dev` shows every generated sprite and the village in its initial, partial and completed states. In production builds this page returns a 404.

## How the art is made

All graphics are original and generated by code, with no image tools or AI images. `scripts/generate-assets.ts` draws on a small RGBA pixel canvas (`scripts/lib/px.ts`). That canvas has no dependencies and encodes PNGs with `node:zlib`. The script writes:

- `public/assets/christmas/**`: transparent PNG sprites at 1× logical resolution (66 files, about 150 KB in total)
- `src/constants/sprites.json`: sprite sizes and per-house anchors (doorstep, chimney, roof top)
- `src/app/opengraph-image.png` and `src/app/icon.png`

The art follows these rules:

- One shared palette (`scripts/lib/palette.ts`).
- Light comes from the moon in the upper left, so every right-facing surface uses the darker colour in its ramp.
- Front-on elevations at a single scale.
- Ordered (Bayer) dithering is used instead of gradients.
- Each house has three aligned layers: `base` (the house at night), `lit` (window glow and light falling on the snow) and `decor` (decorations specific to that house).
- Generation is deterministic because the seeded PRNG gives identical output on every run.

| File                         | Contents                                                                                                      |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `art/background.ts`          | sky, stars, moon, mountains, forest, snow field, paths, foreground drifts (repeating tiles)                   |
| `art/parts.ts`               | walls (plaster, brick, fieldstone, logs, boards), roofs with snow blankets, windows, doors, icicles, drifts   |
| `art/houses.ts`              | red-roof cottage, woodland cabin, half-timbered townhouse, bakery, stone cottage                              |
| `art/tree.ts`, `art/pine.ts` | the village tree (dark and lit layers), tiered pines                                                          |
| `art/gifts.ts`               | 4 wrapping papers (box body and lid as separate layers), 8 gift items                                         |
| `art/decorations.ts`         | wreath, garland, string lights, candles, lanterns, lampposts, snowman, candy cane, gift pile, sparkles, smoke |

To change the art, edit a file under `scripts/art/`, run `pnpm assets:generate`, and review the result at `/dev`. Add `--preview <dir>` to also write upscaled composition sheets.

## How it works

```text
src/
  app/                      layout (fonts, metadata), page, dev preview, OG image, icon
  components/
    christmas/              ChristmasVillage: phase flow, UI bars, delivery flight, sharing
    village/                VillageScene: depth-sorted sprites, selectable houses
    gifts/                  GiftOpening: box → lid → reveal overlay
    effects/                Snowfall: one pixel-snapped canvas
  features/
    village/game.ts         pure reducer + validation (no imports, tested by Node directly)
    village/store.ts        useSyncExternalStore store (server snapshot = null → no hydration mismatch)
    sharing/postcard.ts     1080×1920 card on its own canvas, download, Web Share + fallback
  lib/storage/              the only module that touches LocalStorage
  constants/                copy (all Korean text), scene layout, sprite metadata
scripts/                    asset generator
tests/                      game rule tests
```

- **Scaling.** One art pixel is the CSS length `--px`. It is computed in pure CSS from the viewport so that the 256×384 village core fits between the UI bars. The server HTML is therefore laid out correctly and there is no layout shift. Background layers repeat sideways, so wide screens show more landscape instead of stretched art.
- **Flow.** The phases are `landing → village → opening → selecting → complete`. Each house receives exactly one gift, and all five gifts are different. A delivered house can't be selected again. The drawn gift and its opened state are persisted, so refreshing never draws a new gift.
- **Persistence.** Stored data is validated on load. Corrupted or inconsistent data falls back to a fresh village. Restarting an unfinished village asks for confirmation first.
- **Sharing.** The card is rendered from the same sprites and layout as the scene, never from a screenshot of the page. It is pre-rendered when the village completes, so the share button can call `navigator.share` within the user's click. If file sharing isn't available, the image is downloaded and the app URL is copied to the clipboard.
- **Accessibility.** Houses are real buttons with names and selection state. Every action works with the keyboard. Status changes are announced in a live region. With `prefers-reduced-motion`, decorative loops stop, the delivery flight is skipped, the snow is static, and state changes happen instantly.

## Deployment

The app is fully static: every route is prerendered. On **Vercel**, import the repository with the default Next.js settings. No environment variables are required. `metadataBase` uses `VERCEL_PROJECT_PRODUCTION_URL` automatically. You can override it with `NEXT_PUBLIC_SITE_URL`, which is needed for absolute OG image URLs on other hosts.

For any other static host, add `output: "export"` to `next.config.ts` and upload `out/`.

## Known limitations

- Sharing the image file depends on the platform. Desktop browsers usually use the download and copy-link fallback.
- The share link opens a new, independent village. Villages aren't saved anywhere other than the visitor's own browser.
- In landscape on phones the village is drawn quite small. The layout is designed for portrait.
- There is no audio.
